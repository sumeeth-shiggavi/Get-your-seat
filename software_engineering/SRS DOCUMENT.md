# SOFTWARE REQUIREMENTS SPECIFICATION

## **FUNCTIONAL REQUIREMENTS**

STUDENT 

| ID    | Requirement                                        |

| ----- | -------------------------------------------------- |

| FR-01 | Student shall be able to register                  |

| FR-02 | Student shall be able to login                     |

| FR-03 | Student shall be able to manage profile            |

| FR-04 | Student shall be able to select an examination     |

| FR-05 | Student shall be able to enter rank/score          |

| FR-06 | Student shall be able to search colleges           |

| FR-07 | Student shall be able to filter colleges           |

| FR-08 | Student shall be able to predict suitable colleges |

| FR-09 | Student shall be able to compare colleges          |

| FR-10 | Student shall be able to search counsellors        |

| FR-11 | Student shall be able to book counselling sessions |

| FR-12 | Student shall be able to view appointments         |



COUNSELLOR

| ID    | Requirement                                          |

| ----- | ---------------------------------------------------- |

| FR-13 | Counsellor shall be able to register                 |

| FR-14 | Counsellor shall be able to manage profile           |

| FR-15 | Counsellor shall be able to define availability      |

| FR-16 | Counsellor shall be able to view appointments        |

| FR-17 | Counsellor shall be able to view student information |

| FR-18 | Counsellor shall be able to add counselling notes    |



ADMIN

| ID    | Requirement                     |

| ----- | ------------------------------- |

| FR-19 | Admin shall manage students     |

| FR-20 | Admin shall manage counsellors  |

| FR-21 | Admin shall manage colleges     |

| FR-22 | Admin shall manage courses      |

| FR-23 | Admin shall manage cutoff data  |

| FR-24 | Admin shall manage appointments |

| FR-25 | Admin shall view system reports |



## NON-FUNCTIONAL REQUIREMENTS



Security: Student information must be protected.



Performance: The platform should respond quickly to normal user requests.



Scalability: The system should support increasing numbers of students and colleges.



Reliability: The system should minimize failures during important counselling periods.



Usability: The interface should be simple enough for students who aren't technically experienced.



Maintainability: The code should be modular and easy for developers to update.



Availability :The platform should be available throughout the counselling period with minimal downtime.
